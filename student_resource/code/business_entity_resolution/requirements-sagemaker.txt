# Additional/replacement requirements for running --backend faiss on an AWS
# SageMaker GPU instance (e.g. ml.g4dn, ml.g5, ml.p3 -- anything with an
# NVIDIA GPU + CUDA). Install this on top of requirements.txt.
#
# UPDATE: torch is now a real (not optional) dependency of blocking_faiss.py,
# transitively via src/transliterate.py (the GPU-batched transliteration
# stage uses torch tensor ops so the same module works on both the local
# MPS backend and this CUDA backend). Install a CUDA-matched torch build
# here rather than leaving it out. The torch/lightgbm OpenMP conflict
# documented in blocking_faiss.py's module docstring (and the `import
# lightgbm` first-import ordering guard at the top of that file and of
# transliterate.py's importer) still applies -- keep that ordering intact
# instead of removing torch.
#
# faiss-gpu (PyPI, official Meta/FAIR package as of 1.15.1) bundles its own
# CUDA 12.x runtime via `nvidia-cublas-cu12<13,>=12.6` etc -- confirmed via
# PyPI metadata, no system CUDA toolkit or special index needed.
#
# CRITICAL PIN: torch>=2.10 switched to bundling CUDA 13 runtime libs
# (unsuffixed `nvidia-cublas`, not `nvidia-cublas-cu12`). Installing that
# alongside faiss-gpu's CUDA 12 requirement puts two incompatible CUDA major
# versions' shared libraries on disk at once; faiss's dlopen of libcublas.so.12
# then resolves to a mismatched cublasLt and fails with
# `undefined symbol: cublasLtGetEnvironmentMode` at import time. Confirmed by
# an actual failed SageMaker run (ml.g5.2xlarge, torch==2.14.0) on 2026-09-27.
# torch==2.9.0 is the newest release still on the CUDA 12 line
# (nvidia-cublas-cu12==12.8.4.1, satisfies faiss-gpu's <13,>=12.6 constraint) --
# do not bump torch here past 2.9.x without re-checking both packages' CUDA
# major version pins.
faiss-gpu
torch==2.9.0
